# FIFI Lab 全设备统一完整版动效设计

## 目标

所有支持现代网页标准的浏览器都播放与本地完整版相同的品牌动效，不再因为操作系统或浏览器报告 `prefers-reduced-motion: reduce` 而降低背景波动、猫猫拖尾、工具卡片倾斜或“小猫传送门”的视觉强度。

本次验收保证的是动效的速度、幅度、轨迹密度和完整表现一致。网页无法强制低性能硬件或后台标签页持续输出物理 60 FPS；当浏览器丢帧时，动画必须按真实经过时间推进，不能因为帧数减少而变慢、变淡或减少轨迹数量。

## 已确认根因

当前正式版为 `prefers-reduced-motion: reduce` 单独配置了轻量档：

- 背景画布最多约 15 FPS，波动与鼠标推力缩至完整版的 36%，时间速度缩至 55%。
- 猫猫拖尾的生成间隔从 60 ms 增至 140 ms，最小距离从 9 px 增至 18 px，图标从 30 px 缩至 20 px。
- 工具卡片的跟随倾斜缩至 30%。
- “小猫传送门”改用更短、更弱的动画和更早的跳转。

因此访客看到的轻度表现是既有代码主动选择的结果，不是 GitHub Pages 限制或网络传输导致的帧率下降。

## 统一动效规则

### 背景色块

- 删除 `InteractiveField` 中基于 `prefers-reduced-motion` 的强度、速度和帧率分支。
- 每次绘制仍由 `requestAnimationFrame` 驱动，形变时间继续取自回调时间戳。
- 鼠标跟随从“每帧固定靠近 4%”改为根据两帧之间的真实毫秒差计算。60 FPS 时保持当前手感；30 FPS、15 FPS 或高刷新率屏幕上保持相同的实际跟随速度。
- 页面恢复可见或出现较大时间间隔时限制单次时间步长，防止色块瞬间跳跃。

### 猫猫拖尾

- 删除轻量档的间隔、距离、尺寸与动画时长分支，所有设备使用当前完整版样式。
- 拖尾生成从“依赖浏览器送来多少次 `pointermove`”改为沿两次已知指针位置之间按固定距离补点。
- 优先消费浏览器提供的合并指针事件；无合并事件时仍对路径做等距插值。
- 单次事件设置合理的补点上限，避免窗口切换或异常大跨度造成 DOM 瞬间堆积；上限只保护性能，不改变正常移动时的密度。
- 每个猫猫仍在自身退场动画结束后移除。

### 工具入口与传送门

- 工具卡片在所有设备使用相同倾斜幅度和过渡时间。
- “小猫传送门”在所有设备使用完整关键帧、完整票据动画和 1500 ms 跳转时序。
- 删除仅用于轻量档的 `data-motion="reduced"` 状态与 CSS 覆盖，保留统一的 `data-motion="full"` 作为验收标记。

### 其他动画

本次只统一首页背景、猫猫拖尾、工具入口和打开工具动画。To-Do List、五个小游戏以及其他已经确认的界面与动效不修改。

## 测试与验收

- 单元测试覆盖按真实时间计算的跟随系数，以及猫猫轨迹等距补点与异常跨度上限。
- 浏览器测试分别在默认动态偏好和 `reduce` 动态偏好中执行相同鼠标轨迹，验证：
  - 背景持续变化，且不存在 66 ms 人工限帧分支。
  - 猫猫尺寸、动画时长和同一路径生成数量一致。
  - 工具卡片在相同指针位置获得一致的倾斜幅度。
  - 传送门均标记为完整版，并在相同时间窗口内跳转。
- 桌面宽屏和移动端尺寸继续通过现有布局与溢出测试。
- 提供生产构建临时预览，用户确认后才合并并发布正式站。

## 非目标与限制

- 不实现帧率计数器或用户可见的动效设置。
- 不通过 UA、设备型号或性能评分切换视觉档位。
- 不承诺所有硬件恒定达到 60 FPS，也不在后台标签页绕过浏览器节流策略。
- 不修改已经确认的页面排版、配色和交互入口。
