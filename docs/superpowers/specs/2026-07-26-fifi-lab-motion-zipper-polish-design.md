# FIFI Lab 动效兼容与拉链细节修复设计

日期：2026-07-26

## 目标与范围

本轮只修复首页动效兼容和拉链 To-Do List 的交互细节，不调整已经确认的首页布局、背景造型、工具入口、五个游戏入口、猫猫光标造型与整体配色。

需要解决的用户可见问题：

1. 部分访客设备看不到背景波动、猫猫拖尾和工具传送门动画。
2. 拉链完全展开后，点击拉链头无法收回。
3. 拉链拖动期间，加号会在列表尚未完全展开时提前出现，并且不受列表遮罩控制。
4. 勾选待办时只有突兀的状态跳变，没有完整的勾选与划线反馈。
5. 列表遮罩与下层拉链边缘重合，条目会与粗描边和拉链齿发生穿帮。

## 已确认的根因

### 跨设备动效

正式站资源可以正常加载，普通动态偏好下三类动效均正常工作。问题来自现有的 `prefers-reduced-motion: reduce` 分支：它停止背景绘制与鼠标响应、完全隐藏猫猫拖尾、关闭传送门关键帧，并用全局 CSS 将所有动画和过渡压缩至接近零时长。因此，只要操作系统或浏览器报告“减少动态效果”，网站的品牌动效就会整体消失。

### 点击收回

拉链头的 `pointerdown` 会提前把 `expanded` 改为 `false`，同一次操作随后触发 `click` 时便会被当作“从关闭状态重新打开”。点击与拖拽共用并互相覆盖状态，导致完全展开后单击无法收回。

### 加号与遮罩

拖拽期间根节点仍带有 `open` 类，而加号的显示规则只依赖 `open`。同时，加号位于列表遮罩容器之外，所以它既会提前出现，也不会随袋口裁切。

### 勾选反馈

完成状态目前直接切换字符 `✓`、`text-decoration` 与整行透明度。浏览器没有可以插值的“画勾”和“画线”过程，因而表现为一次突变。

### 遮罩穿帮

内容裁切路径与可见袋口边界完全相同，没有为拉链的粗描边、阴影和齿带预留内侧安全距离。内容虽然被裁切，仍会画到边界笔触的下面。

## 设计方案

### 1. 完整动效与轻量动效

采用双档动效策略，不增加新的设置按钮：

- 普通动态偏好：保留现有完整背景波动、鼠标猫猫拖尾、工具卡片悬停和约 1.5 秒的蛋白传送门动画。
- 减少动态偏好：仍然展示品牌动效，但降低频率、位移与持续时间，不再退化为静止页面。
  - 背景继续缓慢呼吸并响应指针，刷新频率与形变幅度低于完整版。
  - 猫猫光标核心仍跟随鼠标，拖尾数量更少、尺寸更小、消散更快。
  - 工具卡片保留轻微抬升和扫光，不做明显的三维倾斜。
  - 传送门保留清晰可感知的入场、穿越与送达过程，时长约 0.8 秒，减少旋转和长距离位移。
- 删除“全局把所有动画压缩到 0.01 毫秒”的规则，只对可能造成明显眩晕的幅度做定点收敛。

触摸设备没有鼠标悬停，因此不强行伪造悬停；传送门和背景呼吸仍需正常播放。任何设备都不应因为动态偏好而得到完全无动效的页面。

### 2. 拉链点击与拖拽状态机

点击和拖拽使用同一个进度值，但不再在 `pointerdown` 时修改展开状态：

- 按下时记录“按下前是否展开”与起始坐标。
- 移动距离未超过阈值时保持为点击候选，不改变稳定的展开状态。
- 移动距离超过阈值后进入拖拽，进度跟随拉链曲线。
- 拖拽释放后，以进度阈值决定自动吸附到完全展开或完全收回，并屏蔽随后生成的 click。
- 没有发生拖拽时，click 根据按下前的稳定状态执行相反动作：展开变收回，收回变展开。

由此保证鼠标单击、触控单击、鼠标拖拽和触控拖拽互不抢状态。

### 3. 加号层级与出现时机

- 将新增按钮移动到与待办条目相同的动态遮罩容器中，使它与列表共用同一条裁切路径。
- 展开或拖拽过程中，加号保持不可见且不可点击。
- 只有拉链动画到达 100%、面板进入 `interactive` 状态后，加号才做一次短淡入和轻微上移。
- 收回开始的第一帧立刻隐藏并禁用加号；之后列表条目继续按遮罩逐渐收回。
- 八条上限与禁用样式保持不变。

### 4. 勾选与取消勾选动画

完成状态的数据在点击时立即更新，完成计数也立即更新；视觉反馈分三段连续发生：

1. 复选圆圈轻微压下并填色，勾线沿路径画出。
2. 勾线完成后，横线从文字左侧向右侧绘制。
3. 横线完成后，当前条目轻微降色，但不再让整行突然下沉或延迟一秒才变化。

取消勾选时使用较短的反向过程：横线收回、勾线消失、圆圈恢复。输入框仍可编辑，删除按钮行为不变。

### 5. 遮罩安全边

可见袋口路径与内容裁切路径分离：

- 拉链、布料和袋口继续沿现有曲线绘制，外观不改变。
- 内容裁切的下边界沿下层拉链曲线向袋内侧偏移约 18 个 SVG 单位。
- 偏移需要随拉链进度和曲线法线变化，而不是只对整条路径做固定的垂直平移，确保半开状态和完全展开状态都贴合。
- 条目和加号都使用这条收紧后的裁切路径，不能覆盖拉链齿、黑色粗描边或外侧布料。

## 测试与验收

### 自动化测试

- 在普通动态偏好下验证背景画面随时间变化、鼠标移动生成猫猫拖尾、工具卡片获得动态变换。
- 在减少动态偏好下验证上述元素仍然有可见的轻量变化，传送页停留时间足以看到动画，并且不存在全局近零时长规则。
- 验证拉链完全展开后单击会收回，完全收回后单击会展开。
- 验证真实拖拽结束后不会再触发一次反向 click。
- 验证半开和收回阶段加号不可见、不可点击；完全展开后加号可见、可点击。
- 验证加号位于与任务条目相同的裁切容器。
- 验证完成状态会出现可动画的勾线路径和文字横线，并能反向取消。
- 几何单元测试验证内容裁切路径不再等于可见袋口路径，并在半开与全开状态保持安全边。

### 真实浏览器验收

- 在正式尺寸下分别模拟 `no-preference` 与 `reduce`，录取关键帧或截图对比，确认两档都不是静止页面。
- 从正式首页入口打开两个工具，确认传送门动画可见且最终 URL 正确。
- 使用点击和拖拽各完成一次拉开、收回。
- 在 25%、50%、75% 和 100% 拉链进度观察列表、加号与下层拉链边缘，确认无穿帮。
- 勾选和取消一条待办，确认计数立即更新，勾线和横线顺序自然。
